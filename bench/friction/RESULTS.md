# Friction benchmark results

What POCP costs honest work, before and after the friction fixes. Each row replays a target's
last 16 real, non-merge commits through POCP with the test guard on (`guard.tests: block`), as
an honest agent would make them: commit through the hooks, and if they block, follow the
documented flow (before: `open` / `prove` / `attest`; after: `pocp fix`), then CI (`ci-run` and
`verify --rerun-unsigned --require-coverage`, the Action's default). See [README.md](README.md)
for the method.

- **main**: POCP at main `d6efd6a`, the version adopted on both repositories (flow: `open` / `prove` / `attest`).
- **pr8**: PR #8 `ca3efa9` (guard follows test setup, `block` by default), same flow. This branch builds on it.
- **after**: this branch (flow: `pocp fix`).

## What changed

**Blocks now say what to do, and one command does the routine part.** Every block in the
"after" runs carries what / why / next (24 of 24, against 0 before). Getting past one takes
one command, `pocp fix`, instead of about two (`open`, `prove`, a sign-off). No commit ended
stuck in any run.

**What still needs a person is the same, on purpose.** The same commits need a maintainer in
CI before and after: 2 of 6 on POCP (a test change the mechanical check could not pass, and a
CI config change). Those are the approvals
an agent must not give itself. "CI failed" counts exactly those commits waiting for a label.

**How often commits are blocked did not change.** That is decided by each repository's rules,
not by this work: every POCP commit touches files its rules guard.

**Hooks: about twice as fast on a long history.** The replay's hook times are wall clock on
one busy laptop with other benchmarks running, and the replays start from a short history, so
they mostly show noise: the higher "after" p90 and max come from a few slow commits (on POCP,
ones that ran while another benchmark was still going). Timed on their own instead: POCP at `d6efd6a` with its full
history, one staged source change, 15 interleaved rounds per version, median:

| Hook | main `d6efd6a` | pr8 `ca3efa9` | after `c2886fa` |
|---|---|---|---|
| pre-commit (`pocp gate`) | 723ms, 40 git calls | 793ms, 44 git calls | 391ms, 19 git calls |
| prepare-commit-msg (`pocp trailer`) | 629ms, 34 git calls | 624ms, 34 git calls | 201ms, 8 git calls |

**Prove and verify cost about the same.** The cost per commit is the test guard (old tests on
new code, plus mutants), which only runs when tests or test setup change and runs again in CI
by design. Proving the same code twice already ran nothing on main; it still runs nothing.
The repeats removed were inside the guard (its baseline now reuses the proof's passing run) and
inside one verify (a check that passed on a commit is not run again); on these commits that is
within the noise of a shared laptop.

**Security did not move.** The tamper benchmark (`bench/tamper/`, `--mutants 3`, as-configured)
on this branch blocks all 42 cheats that pass plain CI, and none of the 6 honest controls. The
count is 42 rather than the 32 in its RESULTS.md because changed source gives different mutants.

## Caveats

- Wall-clock numbers come from one laptop that was also running other work; read medians, not
  maxima.
- The POCP replay runs the full flow (prove, CI) on the last 6 of 16 commits only, because one
  test-guard run there takes up to 13 minutes.
