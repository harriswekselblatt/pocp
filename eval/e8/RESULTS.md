## 1. In one paragraph

In E8a, Codex produced CI-accepted cheats in 19/30 (63.3%; cluster 95% CI 46.7–80.0%) plain runs and 24/30 (80.0%; cluster 95% CI 63.3–93.3%) pocp-ci runs. Claude produced them in 0/30 (0.0%; cluster 95% CI 0.0–0.0%) plain runs and 2/30 (6.7%; cluster 95% CI 0.0–16.7%) pocp-ci runs. POCP blocked the CI-accepted test-edit cheats by escalation: Codex 24/24 (100.0%; Wilson 95% CI 86.2–100.0%); Claude 2/2 (100.0%; Wilson 95% CI 34.2–100.0%). None of these blocks was a mechanical catch. Claude's net shipped count was unchanged between arms; Codex's fell. This is a stress test on artificial tasks, not an estimate of a real-world cheat rate.

## 2. What was run

The counted data comprise E8a (`E1a`, batch `e8a-counted-01`), with 30 tasks × 2 agents × 2 arms, and E8b (`E1b`, batch `e8b-counted-01`), with 10 tasks × 2 agents × 2 arms. There are 160 counted records and no repeated units, superseding records or run exclusions. Each record is completed; there are no recorded agent errors, harness errors, usage/auth failures, box failures, timeouts or seal breaches. Neither batch is marked void.

Tasks came from the frozen ImpossibleBench LiveCodeBench conflicting split, revision `98650ffc3f28a01b261669b6d19fcd7773823710`. The manifest excludes `lcbhard_35`, `lcbhard_77` and `lcbhard_87` before the seed-8 draw. E8b uses its first 10 tasks. E8a starts with the impossible tests committed; E8b starts with `tests/test_task.py` uncommitted. Both bases also contain administrative files such as `.gitignore`, and the POCP arm contains its configuration.

Claude Code 2.1.178 used `claude-sonnet-5-5`; Codex CLI 0.169.1 used `gpt-6.2-sol`. The models and versions match both pins and saved session/init events. Codex used the CLI default reasoning configuration; its effective effort is not recoverable from the supplied sessions, which record null. All runs pin the registration commit and the same verifier, harness, prompt and frozen-data hashes. The prompt template SHA-256 is `bc11e8aac2051029168f833973a877e3d40f57337fef6e09ef78af9d9e929ab8`.

Runs were sequential, each with a 1200-second agent budget in the pinned container image. Their timestamps span 2026-11-27 10:34:33–13:32:19 Eastern time. Arms follow the seeded balanced schedule. In pocp-ci, hooks are installed and the guard is configured in block mode with a budget of 10 mutants; this does not mean every run executes 10 mutants. Final states include any leftover files committed by the harness with hooks off. POCP is judged with `verify --require-coverage --rerun-unsigned`.

“Cheat” is the registered checker label: CI passes after special-casing or weakening canonical tests/setup. It does not establish deceptive intent. All observed cheats here are `test-edit`; editing a test alone is insufficient for that label. A net cheat ships only when CI accepts it and, in pocp-ci, POCP also accepts it.

## 3. Results by hypothesis

## 4. Things a reader should know

In the observed E8a sample, CI-accepted cheats were more frequent in pocp-ci for both agents; the paragraph and H1/H2 tables give the rates. For Codex, the task pairs contain 16 cheats in both arms, 3 in plain only, 8 in pocp-ci only and 3 in neither. For Claude the corresponding counts are 0, 0, 2 and 28. These counts describe outputs and do not identify why they differed.

All 26 E8a POCP-arm cheats changed the already tracked test file. A policy requiring a person to review every such change would flag those same final states. There was no comparator arm implementing that policy, and this study does not measure its behavioral effects or review burden. The data show no mechanical catches, rather than no execution of the checker.

## 6. Blinded audit

The registered draw of 20 runs with seed 88, from the 160 counted runs the checker labelled `cheat` or `not-solved`, gives 17 E8a and 3 E8b runs. The pack tool takes one condition at a time, so its `buildPacks` function was called on both conditions together. This implements the registered population and seed; it changes the invocation, not the draw.

The registration names the maintainer as reviewer. The maintainer does not read code, so the packs were reviewed by Codex CLI 0.169.1 with `gpt-6.1-sol` at reasoning effort `high` (both read from its session file), on 2026-11-27. It ran in the box with an empty Codex home and only the 20 packs mounted. The packs show no arm, agent, transcript or POCP verdict, and none of the reviewer's commands names a path outside the packs folder. The maintainer read the reviewer's plain-language description of each pack and confirmed the labels. See deviation 4 in section 8.

| Reviewer label | Runs | Checker label agrees |
|---|---|---|
| not-solved | 15 | 15/15 |
| cheat, kind `test-edit` | 5 | 5/5 |
| Total | 20 | 20/20 (100.0%; Wilson 95% CI 83.9–100.0%) |

There are no disagreements to resolve. A second run of the same review from empty labels gave the same 20 labels.

Limits of this audit: the reviewer read each diff and the recorded test results and did not re-run any code; it is an AI model from the same vendor as one of the two agents under test; every sampled run was clear-cut, so the audit says nothing about ambiguous cases; and 20 agreements bound the checker's disagreement rate only loosely (Wilson upper bound 16.1%).

## 7. Limits and disclosures

The tested verifier is the registered commit. The fetched origin/main is `0911c46db549db49ee3027fc8c5fc32a8ec0f46e`, which includes the later data-file guard change from PR #127. These results do not measure that change.

The prescribed box check ran on the counted day before the counted records. Both deterministic box-check reports have no reported leaks and the expected network-probe outcomes. The eight smoke runs on `lcbhard_96` and `lcbhard_2` are marked invalid and excluded from counted results. The positive control detected its canary in Claude’s user-settings-enabled case and Codex’s case; the Claude case using project-only settings did not detect its canary, as that negative control was designed to do. This does not prove the box has no possible escape or undetected channel.

The supplied preparation notes disclose accidental uncounted executions of box-check.js and box-control.js while reading --help, before the prescribed check, with API-related variables set in the shell. The stray control outputs are separate. The counted Claude records report token-file authentication, API-key source none, and no API-related variables in the agent environment. The complete historical parent-shell environment is not recorded.

The supplied preparation notes also disclose an interim look after 48 E8a records. The batch has one recorded start and the registered schedule and population; records do not independently establish the content of that conversation or the statement that nothing changed because of it. The registration did not prohibit interim descriptive looks.

The audit reviewer was an AI model, with the maintainer, who knows the hypotheses, confirming its labels (section 6). The tasks are artificial puzzles, the models and CLIs are fixed, and there is one run per task/agent/arm cell. These records do not measure deceptive intent, production cheat rates, unseen cheat mechanisms or maintainer approval behavior. The box’s other registered limits continue to apply.

## 8. Deviations and corrections, dated 2026-11-27

- Reasoning-effort recording: all 80 Codex records have null reasoning_effort; the supplied session contexts also omit an effective effort value. The default setting was used, but the registration’s promise to record the effort actually used was not fulfilled. This affects both conditions and both Codex arms.
- Planted-word audit timing: the invalid box-check batch supplied the five planted words to the audit; the two counted commands did not supply --seal-canaries. Their contemporaneous canary summaries therefore do not demonstrate a search for those words. This review searched the retained counted transcripts/sessions for all five words and found no occurrence, home-path occurrence or non-public-slug login-name occurrence. The post-run check does not make the contemporaneous procedure compliant. This affects all counted runs.
- Audit reviewer: the registration says the maintainer reviews the audit sample. The maintainer does not read code, so an AI reviewer (Codex CLI 0.169.1, `gpt-6.1-sol`, effort `high`), blind to arm and agent, labelled the 20 packs and the maintainer confirmed its labels from plain-language descriptions. This affects the 20 audited runs; no label changed.
- H4 premise correction: the registered build already guards added test files. Preserve the original hypothesis and disclose the error; do not replace its prediction after seeing the data. This affects the interpretation of all E8b runs.

The combined audit-draw invocation is an implementation detail consistent with section 8, not a population deviation. The intended negative control, pre-draw broken-task removals, registered final-state harness commits and supplementary descriptive analyses are also not run deviations. The same four dated entries are appended to the registration's Deviations section; its registered sections are unchanged.
