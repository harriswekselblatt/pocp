Every number below comes from that file. PREREG §5: E5 is descriptive only, so there are no bars, intervals or tail claims here.

**Unit** (PREREG §1): one gate attempt sequence for one staged subject: every gate evaluation in a repo (all its worktrees) of the same staged-code hash, in time order. The outcome is set by the first `pass`:

- *passed first try*: the first evaluation passed;
- *blocked then passed*: one or more `blocked` before the first `pass`. Time to pass is from the first block to that pass; "blocked evaluations" counts the blocks before it;
- *never passed*: no logged `pass` for that subject. **Rule for attempts with no logged pass:** they count as never passed, and their time is never put into time to pass. Usually the code was changed and re-staged, which makes a new subject; the gap from the first block to the next pass of a *different* subject in the same checkout is shown separately as an upper bound, not as a time to pass.

**A gate evaluation is not always a commit attempt.** The log gets a line from the pre-commit hook, from `pocp gate`, and from each gate check inside `pocp fix` (2–4 per fix). The log does not record which. So "blocked evaluations" overstates commit attempts, and a `pass` logged by `pocp fix` can come a little before the commit that followed it.

**Nothing required:** subjects where every evaluation had no file that any rule requires proof for. Their first-try pass is free, so the substantive rows leave them out.

## Limits

- Covers only the repositories whose logs were read, on one machine (EVAL-PLAN "Limits"). A repository with a handful of sequences gives anecdotes, not rates.
- All work was by AI agents and the maintainer on the same machine, mostly on POCP itself, so this is not a sample of outside use.
- Time to pass is wall clock and includes the agent thinking, running unrelated commands, and machine load. It is not POCP's run time; the proof durations are.
- The log has no field saying whether an evaluation came from the hook, `pocp gate` or `pocp fix`; adding one (`source`) would let "blocked evaluations" become "blocked commit attempts".
- EVAL-PLAN's earlier partial reading counted entries differently; the numbers here supersede it.
